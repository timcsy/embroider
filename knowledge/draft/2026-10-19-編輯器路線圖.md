# 編輯器路線圖（待你確認，確認後才寫進 vision）

怎麼冒出來的：2026-10-19 討論「讓媽媽想到什麼就做得出來」。根公理不變（懂刺繡、不懂電腦的長輩是第一位使用者）；手繪對其他人也有用，但不能讓媽媽的主畫面變複雜。

## 設計準則（驗收時逐條對）
1. 直接動手：拖、拉、點色票，不找選單。
2. 看得到就是繡得到：改了立刻看到預覽，沒有「套用」鈕。
3. 永遠有退路：復原、重做固定位置；刪除不彈確認，改成「剛刪掉的」可拿回。
4. 用她的詞：繡框、顏色、線、填滿、鏡像、整排；不出現圖層、錨點、匯出。
5. 一次只問一件事：選到什麼物件就只顯示它的選項；沒選到時只有「加文字、加圖片、加圖案、畫」。
6. 觸控目標 ≥48px、字 ≥16px、對比高。
7. 擋錯不責備：說明原因並直接幫她修好。
8. 不需先學：第一次一句話指路，之後不再出現。

## 版面（同一套程式碼，響應式）
- 手機直立：畫布佔上半，選中物件後工具列從底部彈出，單手拇指碰得到。
- 平板：畫布為主，工具在側邊；橫放要用多出的寬度，不是把手機版放大。
- 電腦：畫布居中、工具兩側；滑鼠拖移、滾輪縮放、鍵盤微調；不做只能在電腦用的功能（右鍵選單、懸停當唯一說明）。
- 觸控與滑鼠同一套操作邏輯。

- [x] 設計由多個物件組成：文字、圖片（現有轉換）、簡單形狀（圓、方、愛心、線）
- [x] 點選、拖移、雙指縮放與旋轉（滑鼠：拖、角點、滾輪）；選中物件顯示專屬工具列
- [x] 每個物件各自的顏色、字型（文字）、粗細（線與形狀）
- [x] 復原與重做；刪除可拿回；複製；上下層
- [x] 對齊與置中
- [x] 核心：多個物件各自產生針跡，合併後一起適配繡框、一起檢查、同色排一起、線排在填充後
- [x] 現有「文字／圖片」兩個分頁的功能完全保留（既有測試不退步）

**已完成的驗收與做法備註：**
- 核心 `stitch-compose`（19 個測試）；前端 `editor.ts`、`geometry.ts` 為純函式（37 個測試）；端對端 37 個（含手機、平板直放、平板橫放、電腦四種視窗的版面與按鈕大小檢查）。
- 刪除改成「已刪掉，拿回來」；沒做「剛刪掉的」清單，只保留最近一次。
- 對齊只做置中（左右、上下、正中間）；等距排列留到 E3 一起做。
- 兩指縮放旋轉只有數學部分有單元測試，真實觸控要在手機上試（🧑）。

**驗收：**
- 手機、平板、電腦三種視窗的端對端測試：加一行文字、加一張圖、移到角落、縮放、旋轉、換色、復原、複製、刪除後拿回，全都做得到（Playwright）
- 三種視窗下，所有可點的目標 ≥48px、無橫向捲動（自動檢查）
- 多物件設計輸出的檔案通過 pyembroidery 讀回，針都在繡框內，超出會被擋並白話說明（Rust 測試）
- 🧑 媽媽不看說明做出「圖案加一行名字」（實測）

### E2　手繪
- [ ] 手指或滑鼠畫線；選粗細與顏色；線自動走平針或緞面
- [ ] 封閉圖形可選擇填滿
- [ ] 不做壓力感應、筆刷、圖層；進階選項收在進階區，預設全自動
- [ ] 畫完是一個物件，可拖移、縮放、旋轉、複製、復原

**驗收：**
- 畫出的線轉成針跡後，針都落在線上、粗細符合選擇（Rust 測試，沿用 stroke 的測試方法）
- 三種視窗的畫線端對端測試；畫線中途復原正確
- 🧑 媽媽自己畫一個簡單圖案並繡出

### E3　拼布與刺繡常用
- [ ] 整排重複（花邊）與鏡像
- [ ] 字繞圓或弧形
- [ ] 簡單邊框（圓框、方框、花邊）

**驗收：**
- 重複的間距相等、鏡像精確對稱（Rust 測試，誤差以 0.1 mm 計）
- 弧形文字不超出繡框，字的方向正確（測試加預覽截圖）
- 🧑 媽媽做出一個圓形標籤與一條花邊

## 每階段共同的完成條件
- TDD：先寫失敗的測試
- check.sh、verify.sh、vitest、Playwright、svelte-check 全過
- 版面截圖三種尺寸各一張，附在回報
- 介面文字沒有技術術語（現有的字串檢查擴充到新畫面）
- 需要實機或媽媽才能判斷的項目，標 🧑 並列入 quickstart，不假裝已驗證

## 風險
- 手勢手感只能在真的裝置上確認 → 先交出可操作的 E1 給你們試，再繼續。
- 版面重做會碰到幾乎所有前端測試 → 先把現有端對端流程當成不退步的底線。
- 多物件的針跡合併：重疊與順序要定規則 → 重疊時後加的在上面；文字壓在圖片上先提示不擋。

## 已排除
- 壓力感應、筆刷、圖層、自由路徑編輯（錨點）：不符合根公理的「用得順手」，且收益低。
